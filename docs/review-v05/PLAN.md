장식보다 고객의 선택 순서를 정리한다. 메인은 어떤 일을 맡길지, 서비스는 무엇을 얼마에 어디까지 받는지 먼저 답해야 한다. 사용자 의견 7건은 바로 구현하고, 마케팅·개발 8개 상세는 아래 새 구조를 기준으로 개선한다. 실제 고객 사례가 아닌 이미지는 제작 예시로 구분한다.

## 개발·마케팅 전체 구조 재검수

8개 URL을 실제 브라우저에서 열어 본문/헤딩을 service-audit.json으로 보존했다. 검수 기준은 사용자 캡처, v04 코드, 사업 구조 마케팅 v36·영상 v06 및 개발 견적 원문이다. 캡처의 숫자 0은 스크롤 카운트업 초기값이므로 실제 실적으로 해석하지 않는다.

현재 마케팅은 제공 범위·맡는 일·포함 항목이 세 번 반복된다. 개발은 시각 예시가 가격·범위보다 앞서고, 프로그램의 진행 단계와 FAQ가 중복되며, 쇼핑몰에도 독립 서버 소유·소스 인계처럼 플랫폼별 차이를 무시한 안내가 나온다. 자동화/프로그램에 웹사이트 중심 FAQ를 재사용한 점도 수정 대상이다.

### 공통 정보 순서

1. **첫 화면**: 결과 한 문장 → 추천 대상 → 가격/단위 → 상담 버튼과 제공 범위 바로가기.
2. **서비스 선택**: 이 서비스가 맞는 상황 3개. 서로 다른 서비스를 비교하는 짧은 연결.
3. **제공 범위**: 기본 포함 / 별도 협의 / 고객 준비를 한 곳에서 설명. 수량·채널·납품 형태·계약 기준을 함께 표시.
4. **결과물 예시**: 한 가지 구체적인 흐름을 짧게 보여주고 예시임을 표시. 기능·성과를 보장하는 표현 금지.
5. **진행과 확인**: 요구 정리 → 제작/적용 → 실제 사용 검수 → 인계/보고. 단계별 고객 확인 항목 명시.
6. **해당 서비스 FAQ**: 가격 영향 요소, 수정/운영/권리/추가 비용 중 실제 질문 4개.
7. **문의**: 해당 서비스가 미리 선택된 상담 양식. 준비할 자료를 한 문장으로 안내.

## GA4 연결 승인 범위

사용자가 AIO MAKE Analytics 전용 연결과 AIO-MAKE 속성 536780274 보기 권한을 승인했다. Cloud 프로젝트 aio-make-analytics는 이미 존재하는 것을 확인했다. 전용 서비스 계정을 준비하고 속성 Viewer만 부여하며 Analytics Data API를 사용한다. 비밀키는 채팅·Git·브라우저 코드에 기록하지 않는다. 사용자 직접 수행이 필요한 인증 단계가 있으면 화면을 준비한 뒤 한 단계로 안내한다. 실제 API 응답과 대시보드 표시까지 확인해야 연결 완료다.

## 검수 루프

추가 홈 검수에서 개발 홈의 모든 가격이 ‘범위별 협의’인 점, 전체 소스 인계를 일괄 약속하는 제목, 진행 공유/진행 순서의 중복을 확인했다. 마케팅 홈은 통합 운영 설명이 분야 전체의 조건처럼 읽히고, 예시 유입 곡선이 비교 정보보다 앞선다. 이 발견을 바탕으로 두 분야 홈도 서비스 비교 → 가격·핵심 범위 → 명시된 작업 예시 → 진행 방법 → 문의 순서로 재구성한다. 기존 디자인 원본 모듈은 보존하며 새 overview 컴포넌트를 적용한다.

1. 이 계획 → 화면 7건 구현 → 동일 867×884 캡처와 DOM 위치 비교.
