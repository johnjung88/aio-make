## 구현

- `/ko`: 마케팅 운영 중, 영상·개발 오픈 예정. 한국어 메뉴·메타데이터·구조화 데이터.
- `/ko/services/marketing`: 고객 고민, 범위, 자체 프로젝트, 과정, 순번별 가격·조건, 자료, FAQ, 상담.
- `/ko/portfolio`: 자체 프로젝트의 확인된 목적만 안내. 고객 실적·성과 수치·미확인 산출물을 만들지 않음.
- `/ko/resources`: 점검표·상담 준비자료 TXT 다운로드.
- `/ko/quote`: 필수 업체·담당자·연락처·업종·지역·내용·동의, 선택 항목과 유입정보. 서버가 저장을 확인해야 성공 표시.
- 영어 주소 308, 비운영 서비스 307, 기존 보조 사이트맵 308. 현재 경로만 사이트맵에 포함.
- 신규 상담은 별도 `marketing_*` 테이블로 원자적 저장. 기존 문의 테이블·원본 자료는 변경하지 않음.
- `/admin/marketing-consultations`: 원문·상태·메모·다음 행동·Grok 요약·초안 버전·승인/발송/회신·작업 상태·불명확 결과 수동 대조 기록. 기존 `/admin/inbox` 이력 링크 유지.
- `/admin/marketing-content`: 홈·서비스 설명·가격표·자체 프로젝트·자료실 항목별 편집, 새 버전·미리보기·공개/이전본 이력. 공개 변경은 기본 비활성화.
- Slack 알림/승인, Grok 작업 수령/결과, 이메일 발송/수신·배달 결과 API 분리. 토큰/서명·본인/팀/채널·최신 초안·회신 버전 검증.
- 외부 불명확 결과는 `unknown`으로 고정. 재실행 전 이전 프로세스 중단·제공자 기록 대조와 수동 증거 기록 필요. 동일 초안 자동 재발송 없음.

## 검증

- `npm run test:marketing`: 격리 PGlite PostgreSQL과 서명·라우팅 회귀 테스트.
- `npm run build`: 타입 오류·lint 오류를 무시하지 않고 프로덕션 빌드. 기존 비운영 컴포넌트의 이미지/alt 등 경고는 남음.
- HTTP: 308/307, 사이트맵, 관리자 비인증, Slack 비인가/잘못된 서명, 중복 접수, 서비스/언어/동의 거부, 자료 다운로드.
- 실제 Chrome 로컬 브라우저: 가상 상담 접수 → 관리자 조회 → 사람 초안 저장. 8개 비교 화면 가로 넘침 없음, pageerror 없음. 저장 후 응답 유실·새로고침 재시도에서 동일 접수번호 복구, 항목별 콘텐츠 편집·버전 저장·비공개 미리보기도 검증.
- DB: outbox 실패 시 전체 롤백, 중복·변경 페이로드 충돌, 중복 승인, 구 초안/구 회신 승인 거부, 회신 중복, 단일 발송 claim, 불명확 발송 차단, 증거 기반 수동 복구, 성공 발송 상태·후속 회신 연결, Grok 결과 중복, 콘텐츠 이전 버전 보존, anon 접근 차단.

테스트 제공자는 로컬 모의 환경이다. PGlite는 실제 운영 Supabase/PostgREST·서버 간 동시 실행과 동일한 검증 범위가 아니다. 독립 외부 검토는 수행하지 않았다.

## 남은 완료 조건

1. 운영 환경의 정확한 DB 스키마/기존 기록/RLS와 마이그레이션 대조.
2. 개인정보 처리자·보유기간·문의처·위탁/외부 처리 안내 확정 후 동의 안내 버전 설정.
3. Slack 비공개 채널·본인 계정·팀·앱 서명, Grok 실행자 연결·acceptance, 이메일 발신/수신 도메인·웹훅 확인.
4. 승인된 시험 이메일 대상으로 실제 접수 → Slack 초안 → 본인 승인 → 이메일 1회 → 후속 회신 연결. 이 시험 전에는 전체 완료로 표시하지 않음.
5. 정확한 콘텐츠·대상 배포 승인 후 운영 마이그레이션/배포. 개인 카카오톡·영상·개발 상세는 별도 후속.
