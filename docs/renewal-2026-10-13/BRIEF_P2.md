# BRIEF P2 — 컨텐츠 서비스 상세페이지 6종 재기획·재구축

먼저 `COMMON.md`와 `RESULT_P1.md`를 읽는다. 결과는 `RESULT_P2.md`. P1(서비스 6종·레퍼런스 JSON 체계)이 끝난 코드 위에서 작업한다.

## 문제
현재 `/content/services/*` 6개는 `components/guide/studio-services.jsx`(약 1,900줄, 인라인 스타일) 하나의 범용 템플릿에 데이터만 갈아 끼운 것이라 "제대로 된 서비스 상세페이지"로 보이지 않는다. 사용자 요구: **각 서비스를 하나의 실제 서비스 상세페이지처럼 기획해서 탄탄하게** 만든다. 이번 작업의 핵심 단계다.

## 구조
- 새 컴포넌트 `components/content-service/` (서버 컴포넌트 기본, 상호작용이 필요한 부분만 `"use client"`), 클래스 기반 CSS 파일 `components/content-service/content-service.css` (인라인 style 금지, 토큰은 COMMON.md 기준).
- 새 데이터 `lib/content-service-plans.ts`: 서비스별 plan 객체. 마케팅·개발의 `lib/service-plans.ts`와 `components/guide/service-detail.tsx`의 `service-*` 클래스 어휘와 다크 테마(`service-dark`)를 참고해 시각적으로 같은 사이트로 느껴지게 하되, 컨텐츠 전용 섹션은 `content-service-*` 클래스로 만든다.
- `app/(public)/[division]/services/[service]/page.tsx`의 video 분기를 새 컴포넌트로 교체. 기존 `ServiceNavigation`(sticky 서비스 탭 6개)은 유지. 관련 작품 조회는 P1의 `displayWorkCatalog` + `workMatchesService`(primary 또는 related)를 사용한다.
- 기존 `studio-services.jsx`는 교체 후 import가 없으면 삭제하고, 그 안에서만 쓰이던 죽은 코드(`cuts`, `cutNote`, `tabs`, 임시 `motion` 항목)도 함께 정리한다. `webtoon-devices.tsx`, `webtoon-scope.tsx`, `showcase-video.tsx`는 재사용한다. 공유 CSS는 사용처를 grep으로 확인한 뒤 명백히 고아가 된 것만 제거한다.
- 검토 플래그가 꺼진 기본 빌드(고객 작품 없음)에서도 모든 페이지가 정상 렌더되어야 한다. 매칭 작품이 없으면 "제작 사례" 섹션 전체를 숨긴다(빈 카드·가짜 사례 금지).

## 페이지 골격 (모든 서비스 공통, 내용은 서비스마다 고유)
각 섹션은 서비스마다 다른 문장·구성을 가져야 한다. 같은 문장에 이름만 바꾼 복붙은 FAIL.
0. 페이지 내 앵커 내비(sticky): 소개 · 제작 범위 · 사례 · 진행 · FAQ · 문의
1. **히어로** — 서비스명, 한 줄 가치 문장, 보조 설명 2줄 이내, `견적 문의`(해당 서비스 선택된 문의로) / `제작 사례 보기`(#cases) 버튼, 대표 실제 미디어(없으면 해당 서비스 정적 대표 이미지)
2. **이런 상황에 맞습니다** — 고객 상황 3~4개(짧은 문장)
3. **제작 범위·규격** — 포맷·비율·길이/분량·납품 파일·수정 범위를 표/카드로(아래 서비스별 기준 참고). 불확실한 수치는 쓰지 않고 "상담 후 확정"
4. **제작 사례** (`id="cases"`) — 매칭 작품 최대 4개: 실제 미디어(영상은 클릭 시 재생·poster 필수, 웹툰은 페이지 넘겨보기 또는 대표 페이지, 사이트는 브라우저 프레임), 제목·고객사·무엇을 했는지 한 줄, 상세 링크(`/work/<slug>`). 상태 라벨(`제작 완료/제작 후보`)은 `WorkCard`와 동일하게 그대로 표시한다(후보를 완료처럼 보이게 하지 않는다)
5. **제작 프로세스** — 이 서비스 고유 단계 5~6개: 단계명, 하는 일, 산출물, 고객 확인 시점
6. **활용처** — 게시·활용 플랫폼과 규격 연결(예: 인스타 릴스 9:16, 유튜브 쇼츠, 쇼핑몰 상세, 홈페이지 히어로)
7. **진행 방식과 견적** — "맞춤 견적"을 기본으로, 견적에 영향을 주는 요소(분량·난이도·권리·수정 횟수) 설명. 구체 금액·성과 수치·"업계 최저가" 류 금지
8. **FAQ** — 서비스별 4~6개(`studio-faq-answer-` 계열 id/class 규칙은 `tests/seo-http.mjs`의 "video 서비스당 FAQ 3개 이상" 검증을 통과해야 함. 해당 스크립트를 읽고 새 마크업에 맞게 스크립트의 셀렉터를 함께 갱신)
9. **CTA** — 보라색 블록, 해당 서비스로 프리셋된 문의

SEO: 서비스별 `<title>`/description/OG, JSON-LD(`Service` + `FAQPage`)는 기존 `lib/metadata.ts`·구조화 데이터 패턴을 따른다.

## 서비스별 기획 기준 (카피는 직접 쓰되 이 방향을 따른다)

### 웹툰
- 가치: 브랜드·제품 이야기를 읽히는 컷 구성으로. 인스타툰·상세페이지·광고 소재로 쓰는 세로 스크롤형.
- 히어로: 기존 `webtoon-devices.tsx`(PC·폰 목업) + `ShowcaseVideo kind="webtoon"` 유지.
- **1회분 = 12컷** (기존 24컷 아님). `webtoon-scope.tsx`를 12컷으로: `Array.from({length:12})`, 제목 "웹툰 1회분은 12컷으로 제작합니다", 그리드·라벨·`aria-label`("12컷 구성")·`1회분 · 12컷`, 샘플은 《1억의 구단주》 `public/webtoon-v11/cut-01..12.webp` 연속 12컷, 라이트박스 유지. 같은 문구가 들어간 모든 곳을 갱신: FAQ(구 `studio-services.jsx:612`), `lib/guide-content.ts:95`, `lib/content.ts` webtoon 항목, 테스트/스크립트(`tests/seo-http.mjs` 등)에서 24를 참조하는 곳. `grep -rn "24컷\|24 cut\|length: 24"`로 전수 확인, 남은 곳은 RESULT에 사유 기재.
- 규격: 컷 이미지 800×1200 기준(1컷=완성 이미지 1장), 1회 12컷, 대사·말풍선·후보정 포함 여부, 캐릭터 시트 유지 방식. 사례: 웹툰 4작품(페이지 수·컷 수는 JSON 원문 기준; 컷 수가 기록된 것만 표기).
- 프로세스: 메시지·권리 확인 → 시나리오·콘티 → 캐릭터 시트 → 컷 제작 → 말풍선·보정 → 납품(채널별 비율 변환).

### 애니메이션
- 가치: 캐릭터와 장면에 움직임을 줘서 짧은 영상으로. 정지 웹툰을 모션 코믹으로 확장하는 경로 포함.
- 사례: `yofree-outing-motion`, `yofree-night-motion`(웹툰→모션 코믹, 세로 영상).
- 규격: 세로/가로, 길이 15~60초 범위는 "상담 후 확정" 표기 가능, 컷→장면 변환 방식, 음원·자막 포함 여부, 음원 권리는 고객 확인.
- 프로세스: 스토리보드 → 장면 분할·무브 설계 → 모션 제작 → 음향·자막 → 검수.

### AI 인플루언서
- 가치: 일관된 인물로 반복 게시되는 컨텐츠. 얼굴·분위기·말투 가이드 고정.
- 사례: 인물 중심 세로 영상 3작품(`bwl-aqua-ad`, `bwl-cplus-ad`, `bwl-cleanser-ad`)이 관련 사례로 매칭된다. 해당 작품들이 AI로 생성된 인물인지 근거 자료에 없으면 "인물 중심 세로 영상 시안"으로만 표기하고 AI 생성 여부를 단정하지 않는다(RESULT에 확인 필요로 기록).
- 규격: 캐릭터 시트(외형·톤)·게시 주기 단위·1편 길이·플랫폼별 비율. 초상·음성 권리와 AI 생성 고지 기준을 FAQ에 포함(허위·오인 방지).
- 프로세스: 페르소나·콘셉트 → 캐릭터 시트 확정 → 시리즈 기획 → 제작 → 고지 문구·게시 가이드.

### 모션그래픽
- 가치: 제품·브랜드 메시지를 그래픽, 타이포, 장면 전환으로 풀어 짧은 영상으로. 촬영 없이 가능한 소개 영상.
- 사례: `bwl-brand-motion`(16:9 30초), `healernet-motion`(가로 30초 + 세로 15초), `yofree-mg-short`(세로 4안), `yofree-mg30`(세 시나리오·가로세로 4개).
- 규격: 비율(16:9/9:16/1:1)별 출력, 길이 15·30초 기준, 로고·제품 이미지 입력 조건, 자막·BGM, 가로·세로 동시 납품.
- 프로세스: 메시지 정리 → 스타일 프레임 → 모션 설계 → 제작·음향 → 비율별 출력.

### 브랜드 홍보 영상
- 가치: 브랜드가 왜 존재하는지를 한 편에 담는 소개 영상. 홈페이지·IR·전시·SNS 공용.
- 사례: `bwl-brand-motion`, `healernet-motion`, `bwl-brand-ad`(related 매칭).
- 규격: 30~60초 중심(상담 후 확정), 가로 기본 + 세로 컷다운, 자막 버전, 브랜드 가이드(로고·컬러·톤) 입력.
- 프로세스: 브랜드 인터뷰·자료 취합 → 메시지 구조 → 스크립트·스토리보드 → 제작 → 버전별 납품.

### SNS 광고 영상
- 가치: 광고 매체·피드 환경에 맞춘 짧은 소재. 첫 3초 후크, 비율·길이별 변형 세트.
- 사례: `bwl-brand-ad`, `bwl-aqua-ad`, `bwl-cplus-ad`, `bwl-cleanser-ad`, `yofree-mg-short`, `yofree-mg30` 중 노출 가능한 4개(정렬: 영상 우선).
- 규격: 9:16 / 1:1 / 16:9, 6·15·30초 변형, 후크 변형 A/B 수량은 "범위 협의". **광고 성과(전환·클릭률 등)를 약속하거나 수치로 제시하지 않는다.** 매체 광고비·집행은 별도(마케팅 분과 연결 링크 제공).
- 프로세스: 소재 목표·타깃 → 후크·카피 설계 → 제작 → 플랫폼 규격·심의 확인 → 변형 세트 납품.

## 디자인·카피 기준
- 히어로는 첫 화면에서 서비스 이름·가치·실제 미디어가 한 번에 보여야 한다. 제목은 의도한 줄바꿈(`\n` → `<br>` 또는 `white-space: pre-line`)으로 어색한 어절 끊김이 없게 한다.
- 섹션 간 시각 리듬: 같은 카드 격자가 반복되지 않게 서비스 특성에 맞는 레이아웃(표, 타임라인, 비교, 미디어 중심)을 섞는다.
- 모든 미디어에 크기 지정(CLS 방지), 영상은 `preload="none"` + poster, 모바일에서 세로 영상 비율 유지.
- 카피는 짧은 문장, 고객 관점, 구체 명사. COMMON.md의 금지 문체 준수. 서비스 간 복붙 문장 금지.
