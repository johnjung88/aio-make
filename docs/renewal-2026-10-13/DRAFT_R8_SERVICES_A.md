## 1. 공통 블록 가운데 정렬 명세 (가격·과정·FAQ, 3개 서비스와 나머지 3개 서비스에 모두 적용)

### 1-1. 섹션 머리

세 블록 모두 `CsSectionHead`에 `align="center"`를 준다(이미 구현된 prop). eyebrow, h2, lead가 컨테이너 가운데에 오고 PC·모바일이 같다. `--read` 컨테이너(현재 880, 1440 이상에서 넓은 컨테이너 왼쪽 끝에 붙음)는 가운데 변형이 필요하다. `theme.css`의 `.cs-container--read`에 짝 클래스 `.cs-container--read-center { margin-inline: auto }`를 추가해 과정·FAQ가 쓴다.

### 1-3. 과정 (진행 방식)

현재는 `번호 | 제목 | 설명+확인` 3열 행이다(img85). 가운데 정렬 기준의 기본안은 **행 구조를 유지하되 세로로 쌓아 가운데에 놓는 것**이다.

| 요소 | 360~767 | 768 이상 |
|---|---|---|
| 컨테이너 | `.cs-container--read-center`, 폭 100% | 최대 폭 880, 가운데 |
| 행 `.cs-step` | `display:grid; justify-items:center; text-align:center`, 위 가는 선, 세로 패딩 24 | 같음, 세로 패딩 28. 3열 격자(`56px / 0.8fr / 1.4fr`) 삭제, 1열 |
| 행 안 순서 | 번호(`cs-t-num`, accent) → 제목(`cs-t-h3`) → 설명(`cs-t-small`, `max-width:560px`) → "함께 확인 + 내용" 한 줄(wrap 허용) | 같음 |
| 마지막 행 | 아래 가는 선 추가(`.cs-step:last-child{border-bottom}`) | 같음 |
| 행 높이 | 약 150(설명 2줄) | 약 132 |

단계가 6개라서 PC 약 800px, 모바일 약 900px이다. 높이를 줄이고 싶으면 **대안 B**로 1024 이상에서 3열×2행 격자(각 칸 위 가는 선, 칸 안 가운데 정렬)를 쓴다. 기본안은 img85와 가장 가까운 행 구조이며 선택은 사용자 몫이다(§6-1).

## 2. 웹툰 `/content/services/webtoon`

### 2-1. 현재 진단

현재 순서: 히어로(표지 컷 1장) → 12컷 3D 리더 → 모션코믹(영상 1 + 맡기는 방법 2) → 가격 → 진행 4행 → 사례(검토판) → FAQ 5 → 문의 → 다른 서비스. R6 측정 문서 높이(검토판 포함) 1440 8,828 · 390 12,226.

- 히어로가 정지 컷 1장이라 "무엇을 만드는 서비스인지"가 첫 화면에서 움직임으로 전달되지 않는다(사용자 요청: 30초 웹툰 특화 영상).
- 웹툰이 어떤 이야기 형식으로 쓰이는지(공감 장면형·브랜드 이야기형·제품 집중형) 보여주는 구간이 없고 소재가 구단주 1편뿐이라 "제품 웹툰"의 폭이 안 보인다.
- 줄거리, 콘티, 작화, 식자라는 실제 공정이 진행 4행에 한 줄씩만 있고, 한 컷이 어떻게 완성되는지 시각 근거가 없다.
- 12컷과 24컷의 차이, 제품이 어떻게 그려지는지, 모션코믹만 맡길 수 있는지 같은 구매 전 질문이 FAQ 3개에 흩어져 있다.
- 가격·과정·FAQ가 왼쪽 정렬이라 위아래 섹션 리듬이 단조롭다(img84~86).

## 3. 애니메이션 `/content/services/animation`

### 3-1. 현재 진단

현재 순서: 히어로(텍스트 + 정지 이미지 1장) → 영상 레퍼런스 그리드(슬롯 3개 중 히어로와 같은 이미지를 빼면 2칸, 모두 정지 이미지) → 가격 2칸 → 진행 4행 → FAQ 5 → 문의 → 다른 서비스. R6 측정 문서 높이(검토판 포함) 1440 7,660 · 390 9,311로 6개 서비스 중 가장 짧다.

- 애니메이션이 어떤 형식으로 쓰이는지(브랜드 캐릭터, 제품 설명, 이야기) 설명이 없고, 30초와 60초가 어떻게 다른지도 없다.
- 실제 공정인 캐릭터 설정, 스토리보드, 애니매틱, 작화·모션, 사운드가 진행 4행의 "제작·최종안" 한 줄에 뭉쳐 있어 제작 품질과 사전 확인 단계가 드러나지 않는다.
- 레퍼런스가 정지 이미지 2칸뿐이라 "움직이는 영상"이라는 서비스 정체성이 약하다. 지금 데이터는 id 문자열 배열이라 캡션·길이 같은 정보를 못 담는다.
- 히어로도 정지 이미지라 첫 화면에서 움직임이 없다.
- 구조 없이 소재가 늘면 그리드만 길어진다. 구조를 먼저 완성해 소재가 늘어도 페이지가 깨지지 않게 해야 한다.

```ts
export type AnimationReference = {
  /** example-media 슬롯 id(영상은 src+poster, 이미지는 src) */
  slot: string;
  /** 타일 캡션, 생략 가능 */
  caption?: string;
  /** 길이 칩, 생략 가능(예: "30초") */
  length?: "30초" | "60초";
};

export const animationReferences: readonly AnimationReference[] = [
  { slot: "animation-scene-2", length: "30초" },
  { slot: "animation-scene-3" },
  // 영상 한 편 추가 = 슬롯을 example-media.ts에 한 줄 만들고 여기 한 줄 더하기
];
```

  타일은 영상 슬롯이면 `LoopVideo`(무음, 화면 안에서만 재생), 이미지 슬롯이면 켄번스 이미지, 둘 다 슬롯 `label`을 태그로 단다. 슬롯 `src`가 빈 문자열이면 그리지 않는다. 길이 칩과 캡션은 있을 때만 그린다. 0개면 섹션 전체 생략. 7개 이상이면 `더 보기`.
- `animationSignature`는 `forms`, `character`, `storyboard`(steps, timeline, foot), `reference` 키를 가진다. `empty` 키는 삭제한다.
- 스타일은 `animation.css`에 클래스로 쓴다(인라인 style 금지). 타임라인 칸 폭은 `grid-template-columns:repeat(6,1fr)`(모바일 `repeat(3,1fr)`).
- 테스트 갱신 대상: `content-site-wpa.test.mjs`의 레퍼런스 id 배열 기대값과 "빈 면" 문구 기대값, 가운데 정렬 3블록 기대값.
