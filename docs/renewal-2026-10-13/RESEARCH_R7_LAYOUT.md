## 0. 먼저 알아둘 것

1. **측정 대상 3215는 `8a7f677` 빌드다**(R6 검증 시점). `b2ecda9`(R6 FIX1: 웹툰 "함께 제작" 배지 이동)는 소스에는 있으나 3215에는 반영되지 않았다. 5번 항목 측정값(배지가 첫 박스 안)은 사용자가 본 화면과 같고, 소스는 이미 한 단계 바뀌어 있다.
2. 측정 방법: 새 서버·빌드 없이 3215에 헤드리스 Chrome(playwright-core, `.qa/r6-verify/lib.cjs`와 같은 경로)으로 접속해 360·390·430·768·1024·1440px에서 `getBoundingClientRect`·`getComputedStyle`을 기록했다. 390 이하는 모바일 에뮬레이션(터치). 원자료와 스크린샷 76장은 세션 임시 폴더에만 두었고 저장소에는 넣지 않았다.
3. 사용자 스크린샷의 가로 폭은 316~666px다. 사용자는 모바일·소형 폭으로 보고 있다. 스크린샷 안의 일부 왼쪽 잘림(img40, img42에서 글자가 화면 맨 왼쪽에 붙음)은 캡처 자체가 잘린 것이고 실제 좌우 여백은 20px다(측정).
4. 실제 화면에서 확인한 핵심 원인 4가지(상세는 각 항목).
   - 메인 마케팅 4박스에서 번호와 제목 사이가 벌어지는 것은 전역 `.eyebrow { margin-bottom: 26px }`(globals.css:178-184) 때문이다.
   - 메인 설명문은 `text-wrap`이 없어 문장 중간에서 끊기고 둘째 줄이 짧게 남는다.
   - 컨텐츠 하단 상담 바는 `<768`에서만 렌더되고(≥768은 `display:none`), 글자는 왼쪽·버튼은 오른쪽 끝으로 `flex:1`이 벌려 놓는다. 색은 무채색 하나다.
   - 컨텐츠 푸터·PROCESS는 모두 왼쪽 정렬 한 가지이며 폰트 14px(링크)·13px(사업자정보)가 기준이다.
