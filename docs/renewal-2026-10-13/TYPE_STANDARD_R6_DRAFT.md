## 0. 먼저 알아야 할 사실

1. 컨텐츠 사이트는 이미 글자 토큰 체계(`--cs-t-*`, `.cs-t-*`)와 8px 단위 간격 토큰(`--cs-s1..s9`)을 갖고 있다. 인라인 `style` 0건, 글자 속성은 서비스 CSS에 거의 없다. 즉 값이 없는 것이 아니라 **값이 서로 덮어쓰고(토큰 중복), 쓰는 방식이 제각각**인 상태다.
2. 메인 사이트(`app/globals.css`의 `--type-*`)와 컨텐츠 사이트(`--cs-t-*`)가 비슷하지만 다른 값을 따로 갖고 있다(H1 78 vs 76, H2 52 vs 48, 섹션 여백 128 vs 140). 이번 기준은 **한 벌의 값**을 정하고 두 토큰 이름에 같은 값을 넣는다.
3. 사용자 불만의 상당 부분은 글자 크기가 아니라 구조에서 나온다. 모든 섹션의 위 선(`border-top`), 항목마다 박스, 섹션마다 140px 위아래 여백, 히어로 요소 8종이 겹쳐 페이지가 길고 산만해진다(수치는 2·7장).

### 원칙 9개

1. **기본 정렬은 좌측 하나.** 로고·헤더·eyebrow·제목·본문·카드 글자가 같은 왼쪽 선을 쓴다. 가운데 정렬은 4장의 예외 2곳에서만.
2. **한 섹션은 한 메시지.** 섹션 제목이 주장 문장이다. 제목 + 리드 1개 + 내용 객체 1개 + 버튼 최대 1개.
3. **항목은 3~4개 이내.** 가격 2~3, 단계 4, FAQ 5, 사례 4~6. 넘으면 줄이거나 나눈다.
4. **박스는 비교하거나 묶어야 할 때만.** 목록은 가는 선과 여백으로 구분한다(7장).
5. **히어로는 요소 5개 이내.** eyebrow(선택), H1, 리드 한 문장, 가격 한 줄, 버튼.
6. **같은 사실은 한 곳에서만.** 12컷·24컷 같은 정보가 히어로, 가격, 범위, FAQ에 반복되지 않게 한다(R6 지적: 중복 반복).
7. **설명보다 결과물.** 영상·이미지 자리가 글보다 먼저 온다. 영상이 아직 없으면 자리표시는 비율 박스와 한 줄 설명뿐이다.
8. **여백이 구분자다.** 섹션 구분 선, 배경색 교차, 카드 틀을 동시에 쓰지 않는다. 하나만 쓴다.
9. **숫자는 확정된 것만.** 수정 횟수, 컷 수, 가격. 근거 없는 수치와 가상 성과 금지(`COMMON.md`).

규칙

- 굵기는 400·500·650·700·750만 쓴다. 한 화면에서 서로 다른 굵기 4종 이내.

## 4. 정렬 규칙

1. **좌측 기준 하나.** 헤더 로고의 왼쪽 선 = 섹션 eyebrow·제목·리드·본문·카드 글자의 왼쪽 선. 모든 섹션이 같은 `.cs-container`를 쓴다.
2. **가운데 정렬 허용은 2곳.**
   - 홈 영상 히어로처럼 미디어가 좌우 대칭이고 요소가 제목·부제·버튼뿐일 때.
   - 페이지 맨 아래 닫는 문구(제목 1줄 + 버튼 1개)일 때.
   그 외 가운데 정렬 금지. 특히 3줄 이상 문단, 카드 글자, 미디어 아래 캡션, 숫자 설명, 단계 설명.
3. **한 블록 안에서 정렬을 섞지 않는다.** eyebrow만 가운데, 제목만 가운데, 본문 좌측 같은 조합 금지.
4. **글+미디어 배치.** 12열 격자에서 글 5열 + 미디어 7열(또는 6+6)만 쓴다. 섹션 안은 위쪽 정렬(`align-items:start`), 세로 가운데는 히어로에서 미디어가 글보다 클 때만.
5. **버튼·링크.** 좌측 섹션에서는 글 왼쪽 선에 맞춰 둔다. 모바일(≤479)에서 주 버튼은 콘텐츠 폭 전체.
6. **숫자와 단위.** 가격 `10만 원`과 `부가세 별도`는 같은 기준선(baseline)에 두고 왼쪽 정렬. 가격 비교 칸은 숫자 시작 위치를 맞춘다.
7. **목록 항목.** 번호(14px) + 제목 + 설명을 한 줄 격자로(번호 열 고정 40px). 항목 높이를 맞추려고 `min-height`를 주지 않는다.
8. **그리드 열 수는 2 또는 3.** 4열 이상은 미디어 썸네일만. 같은 섹션의 항목은 같은 폭, 링크는 항목 맨 아래.
9. **캐러셀 컨트롤은 캐러셀 가장자리**에 붙인다(R6 2-3). 컨트롤이 글 정렬선에 끼어들지 않게 한다.
10. **모바일.** 전부 단일 열 좌측. 가운데 정렬 예외(2번)도 모바일에서는 좌측으로 돌린다.

## 6. 카피 톤 규칙

기존 `BRIEF_P2R.md` 6-1 규칙(합니다체, 쉼표 한 문장 1개 이하, 금지어 목록, 마침표 규칙, `컨텐츠` 표기)을 유지하고 아래를 더한다.

1. **문장 길이.** 제목 2줄 이내. 리드 1문장 40자 안팎(최대 60자). 카드·단계 설명 1문장 40자 이내, 2문장까지. 문단은 3문장 이내.
2. **어미.** 본문은 `~합니다`. 제목·라벨·칩·버튼은 명사형이나 명령형(`상담 신청`). 같은 어미가 세 문장 연속이면 하나를 명사형으로 바꾼다.
3. **마침표.** 제목·라벨·칩·태그·버튼·한 문장 리드는 없음, 두 문장 이상이면 문장마다 있음(현행). 의문형 제목, 느낌표, 말줄임표 금지.
4. **섹션 제목 = 결론.** 설명 대신 약속이나 사실로 쓴다. `제작 과정`보다 `확인하고 나서 만듭니다`. 단 제목에 수식어를 쌓지 않는다.
5. **금지 구조.**
   - `A가 아니라 B`, `A 대신 B`(대조 반전)
   - `A, B, C 없이` 식 부정 나열
   - 같은 구조 문장 3연속(`~를 합니다. ~를 합니다. ~를 합니다.`)과 명사 3연속 나열(`기획, 제작, 납품`을 설명 없이 반복)
   - 문장 끝에 쉼표절을 이어 붙이는 문체
   - `~을 통해`, `~에 대해`, `~할 수 있습니다`, `~에 최적화된`, `~를 제공합니다`(번역투)
   - 최고·완벽·혁신 등 과장어(기존 금지 정규식)
6. **구체어.** 막연한 `전문적인`, `다양한`, `맞춤형` 대신 숫자와 대상(컷 수, 수정 횟수, 납품 형식). 확정 근거 없는 수치는 쓰지 않고 `UNKNOWN`으로 표기해 사용자에게 묻는다.
7. **한 사실 한 곳.** 같은 사실(컷 수, 가격, 수정 횟수)을 두 섹션 이상에 쓰지 않는다. 필요하면 링크로 연결.
8. **용어 고정.** 상담 버튼은 `상담 신청` 하나. 가격은 `N만 원부터 · 부가세 별도` 한 형식. `컨텐츠`로 표기. 한 페이지에서 같은 대상을 다른 이름으로 부르지 않는다.
9. **영문.** eyebrow(대문자 3단어 이하)와 로고 잠금에만. 이번 기준에서는 eyebrow를 히어로와, 영역 이름이 꼭 필요한 섹션에만 두고 FAQ·닫는 문구에는 두지 않는다.
10. **쓴 뒤 점검.** `humanizer`와 위 금지 구조 정규식으로 한 번 훑고 RESULT에 고친 문장을 남긴다.

## 7. 박스·장식 사용 허용 기준

허용(이 경우에만 틀을 쓴다)

| 허용 사유 | 예 | 틀 형식 |
|---|---|---|
| 병렬 비교 | 가격 플랜 2~3개 | 테두리 1px + 면 없음 또는 면만. 모서리 14px |

| 미디어 틀 | 영상·이미지 비율 박스 | 모서리 6~14px, 자르기 |

| 강조 1개 | 선택한 플랜 한 개 | 강조색 테두리. 한 페이지 최대 1개 |

금지

- 글 항목마다 박스(`.cs-type-card`, `.cs-scope-col`, `.cs-related-card`, `.cs-insight-card`의 테두리+면+패딩 조합). 대체: 위쪽 가는 선 1px + 패딩 24 + 제목/설명, 열 사이는 여백.
- 박스 안의 박스(`.cs-step-check`, 히어로 `.cs-price` 칩).
- 섹션 전체 `border-top`과 배경 교차를 동시에 쓰기. 하나만(권장: 여백만, 필요한 곳 한정 선 1개).
- 테두리와 면을 동시에 쓰기. 둘 중 하나.
- 기울임·그림자·오프셋 그림자·플로팅·`예시` 스탬프·큰 장식 숫자·장식용 도형.
- 같은 정보를 칩, 태그, 캡션으로 반복하기. 태그는 미디어 위 라벨 한 개.

모서리: 6(미디어 작은 틀) · 14(카드) · pill(버튼·칩)만. 24px와 임의 값 삭제. 그림자는 시트·팝업에만.

## 8. 페이지 구성 틀과 길이 예산

서비스 페이지 기본 골격(요소 수는 상한):

1. 히어로: eyebrow, H1, 리드 1문장, 가격 한 줄, 상담 신청 버튼 1개(+텍스트 링크 최대 1). facts·주 버튼 2개·주석 제거
2. 결과물 영역: 영상/이미지 자리. 자리표시일 때는 비율 박스 + 캡션 한 줄
3. 제작 방식: 단계 4개 이내(번호 + 제목 + 설명 1~2문장 + 확정된 확인 항목), 박스 없음
4. 가격: 플랜 2~3개, 2개면 모바일에서도 2열. 안내 문장은 한 곳에서만
5. FAQ: 5개 이내. 읽기 폭 컨테이너
6. 닫는 문구 + 문의(좌측 기준, 폼이 같은 화면에)
7. 관련 서비스: 다섯 줄 목록(서비스명 + 한 줄 설명 + 가격). 박스 없이 행, 2~3열

목표(참고치, 구현 뒤 측정): 데스크톱 1440 전체 높이 약 4,500px 이하, 섹션 6개 이하(히어로·푸터 제외). 모바일 390에서 화면 9개 이하.

관련 서비스 행 예시(R6 2-6): `애니메이션 · 캐릭터와 장면을 움직이는 영상 · 30만 원부터`처럼 이름·한 줄 설명·가격을 같은 행에 둔다. 2열(≥768), 3열(≥1024).
