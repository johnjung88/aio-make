## 로컬 실행

`npm run build` 이후 `npm run admin:local` 실행

관리자 주소는 http://127.0.0.1:3111/admin 이며 기존 로컬 관리자 계정을 사용한다
외부 주소/Vercel에서는 관리자와 자료 API를 사용할 수 없다
데이터는 LOCAL_DATA_DIR에 유지되므로 코드 작업트리 교체와 별개로 보존한다
한 저장소는 한 서버 프로세스에서만 연다
서버를 실행하고 관리자를 열어둔 동안에만 Gmail을 5분마다 수집한다
PC가 꺼져도 Gmail에 남은 접수 이메일을 다음 실행 때 가져온다

## Gmail 연결 완료에 필요한 사용자 설정

현재 Google Cloud aio-make-analytics 프로젝트는 OAuth 클라이언트와 동의 화면이 미설정이다
GA4 서비스 계정은 작동하지만 Gmail 개인 계정을 대신 읽거나 발송할 수 없다

1. Google Cloud에서 Gmail API를 활성화하고 OAuth 동의 화면을 구성
2. 테스트 사용자를 쓰는 경우 aiomake2023@gmail.com 등록
3. 웹 애플리케이션 OAuth 클라이언트 생성 및 리디렉션 URI 등록
   `http://127.0.0.1:3111/api/admin/google/callback`
4. 클라이언트 ID/secret을 비공개 .env.local에 설정하고 서버 재시작
5. 관리자 연결·백업에서 aiomake2023@gmail.com 읽기 연결과 발송 연결을 각각 승인
6. 실제 테스트 문의를 발송하고 Gmail 도착 → 로컬 수집 → 상담 저장을 확인
7. Vercel 서버에는 발송용 인증과 동일한 서명 비밀만 설정하고 읽기 인증은 복사하지 않음
8. 공개 /api/contact의 배포 환경 요청 제한을 확인한 다음 CONTACT_PUBLIC_ENABLED=true 적용

새 인증 정보 생성과 Google 권한 부여는 사용자 참여가 필요하다
Google OAuth 앱이 Testing 상태이면 갱신 토큰의 유효기간 제한으로 재연결이 필요할 수 있다
설정·검증 전에는 온라인 접수를 성공으로 표시하지 않으며 이메일 주소를 안내한다
문의 백업에는 인증 토큰이 포함되지 않는다

## 검증 기록

- 기존 16개 + 신규 로컬 통합 1개 테스트 통과
- 신규 통합 검증: 별도 프로세스 재시작 영속성, 상태·메모, 중복 제거, 서명 변조 거부,
  암호화, Gmail 수집 실패 시 커서 유지, 발송 실패를 성공 처리하지 않음, Vercel 접근 차단
- 실제 로컬 API: 인증, 비로그인 차단, CSRF, 백업·비덮어쓰기 복원, CSV, 공개 56경로 HTTP200
- 실제 GA4 7/28/90일 응답 및 관리자 화면 확인
- 브라우저: 문의 선택 색상, 확대/닫기, FAQ, PC/모바일 레이아웃, 별도 테스트 저장소 상담 저장
- Gmail 실제 발송·실제 수집·운영 수신은 OAuth 미설정으로 아직 검증하지 못함
- 브라우저 확인은 Chrome의 뷰포트 검사이며 실제 휴대전화 검증은 아님
