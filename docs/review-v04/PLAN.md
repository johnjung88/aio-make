## 벤치마킹과 적용할 원칙

- [Work & Co 서비스 구조](https://work.co/company/): 서비스 역량·제공 범위를 명확한 묶음으로 설명한다. 회사 규모/실적/고객은 차용하지 않는다.
- [IBM Carbon 대시보드](https://www.carbondesignsystem.com/building-blocks/data-visualization/dashboards): 핵심 지표 우선, 같은 기간/단위/색, 상세 탐색의 다음 행동을 적용한다.
- [IBM Carbon 빈 상태](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states): 비어 있음·시스템 실패·권한/연결 부족을 분리한다.
- [Google Analytics Data API](https://developers.google.com/analytics/devguides/reporting/data/v1/quickstart): 서버 읽기 인증·속성 권한, runReport 집계 계약을 따른다. 측정 ID는 조회 인증이 아니다.
- [Skills 디렉터리](https://www.skills.sh/)와 설치된 스킬을 확인. product-design:audit(현행 캡처), agent-reach(Exa 사례 검색), find-skills(후보 탐색), vercel:react-best-practices(요청 분리·접근성·컴포넌트 품질)를 선택한다. 새 스킬 설치는 필요하지 않다.

## 작업 순서와 검증 루프

1. 현재 캡처·코드·문구 전수 목록 작성 → 위 계획 확정.
2. 공통 탐색/서체/반응형/콘텐츠 링크 수정, 모든 서비스에 적용.
3. 어드민 개요·목록·통계·연결 상태 수정, GA4 API/상태 모델/읽기 연결 경로 구현.
4. 같은 크기의 실제 브라우저에서 다시 확인 → 남은 문제 재수정. 최소 2회 개선 루프. 회차당 약 45분 단위로 증거와 남은 문제를 남기며 결함이 남으면 연장한다.
5. lint/type/build, 의미 있는 GA4 집계·실패·기간 테스트, 기존 단위/SQL, 실제 로컬 문의/CMS HTTP 동선 회귀 시험.
6. 공개 56URL·14서비스 각각 확인, 360/390/768/1440px, 메뉴/탭/폼/로그인/목록/통계 기간 선택. HTTP 검사와 브라우저 검증, 운영 연결을 분리 기록한다.
